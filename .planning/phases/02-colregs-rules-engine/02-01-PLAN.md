<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `cpa()`'s `Result` output -> `riskOfCollision()` | A caller could in principle construct an `ok({ tcpaMinutes: NaN, dcpaNm: NaN })`-shaped object directly (bypassing `cpa()`'s own `Number.isFinite` guard), though the only real caller in this codebase is Plan 02's `classifyEncounter()`, which always sources this value from `cpa()` itself. |
| Direct object-literal construction -> `vesselPriority()`/`rule18Overrides()` | A caller can construct a `Vessel`-shaped object with a `type` value outside the 5-member `VesselType` union (bypassing `VesselTypeSchema.parse()`), since TypeScript structural typing does not enforce runtime validation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `src/domain/colregs/risk-of-collision.ts` | accept | `riskOfCollision()`'s numeric comparisons (`tcpaMinutes > 0`, `dcpaNm <= threshold`) fail-closed to `false` for `NaN` input (any comparison with `NaN` is `false` in JS) — a corrupted `Result.value` degrades safely to "no risk" rather than a silently-wrong "risk." No additional guard is added here because the genuine input boundary (raw vessel numeric fields) is already covered by Phase 1's `cpa()` `Number.isFinite` guard (T-01-03); duplicating it here would guard a value that has already passed through that boundary in every real call path. |
| T-02-02 | Tampering | `src/domain/colregs/vessel-priority.ts` | accept | A `VesselType` value outside the 5-member union would make `PRIORITY[type]` return `undefined`; `undefined < number` is always `false` in JS, so `rule18Overrides()` degrades to "no override" rather than throwing. This is a low-risk, low-likelihood tampering vector already covered by Phase 1's `VesselTypeSchema` Zod enum validation (T-01-01) at the actual construction boundary; `Record&lt;VesselType, number&gt;`'s compile-time exhaustiveness is sufficient for all type-respecting call paths. |

No `high`-severity threats apply to this plan — both functions are pure, framework-free derivations over already-validated numeric/enum data with no I/O, network, auth, or persistence surface (per 02-RESEARCH.md's Security Domain section).

</threat_model>
