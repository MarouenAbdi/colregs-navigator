## Visual Focal Point

**Primary visual anchor:** the full-width verdict banner card (`Rule 15` badge + "Crossing" title + one-line plain-English description + two role badges) sitting directly above the chart — this is the single most important element per `claude-design-prompt.json`'s own "signature moments to nail" list ("large, confident, immediate"). **Secondary anchor:** the chart itself (left column, ~55-60% width) — the live drag/rotate interaction is the product's core loop. **Tertiary:** the Reasoning Trail card — explanatory depth, deliberately smaller/quieter than the verdict banner per the design's own type-scale (verdict title reuses the Heading role at 24px, the section's largest text short of the Hero-only Display role; trail body text is Body-role 16px). The 6-chip preset row and the two vessel-control cards are utility/input elements, intentionally the quietest visual layer (outlined pills, muted borders) so they never compete with the verdict banner or chart for attention.

## Spacing Scale

Declared values (multiples of 4) — **identical to Phase 6/7's shared scale** (SCAF-06: one shared location, reused not redeclared):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (status pill dot↔text, trail number↔connecting line, Reset icon↔label) |
| sm | 8px | Compact spacing (badge/chip internal padding, instrument-readout tile internal gap) |
| md | 16px | Gap between chart column and reasoning column at ≥900px; gap inside the reasoning column between Instrument-Readouts card, status pill, and Reasoning-Trail card; gap between the two vessel-control cards |
| lg | 24px | Card internal padding (verdict banner, instrument-readouts, reasoning-trail, vessel-control cards all use `CardContent`/`CardHeader` at this padding) |
| xl | 32px | Vertical gap between the section's header row (eyebrow/heading/subhead + Reset button) and the chip row; vertical gap between the 2-col grid and the full-width controls row below it |
| 2xl | 48px | Vertical padding above/below the entire Sandbox section |
| 3xl | 64px | Inherited from Phase 6's sticky Header height / `scroll-padding-top: 64px` — `#sandbox` anchor target (already wired by Phase 7) |

**Exceptions:**
- Desktop 2-column grid ratio is `minmax(0,3fr) minmax(0,2fr)` (chart ≈60%, reasoning column ≈40%) — a proportional grid-template value, not a spacing-scale token (see Layout below).
- Custom breakpoints `900px` (2-col → 1-col, SBOX-05/D-06) and `640px` (stacked vessel-control cards, SBOX-05) — layout breakpoints, not spacing values. `900px` is already registered as `--breakpoint-hero: 900px` (Phase 7) — reuse the same named variant here rather than re-registering; `640px` is Tailwind's default `sm:` breakpoint, no new token needed.
- Chip pill height ≈36px (shadcn `Button` default/`sm` height) — component sizing, not a spacing-scale value.

## Layout

**Desktop (≥900px), top to bottom:**
1. Section header row: eyebrow "Interactive sandbox · night-display mode" + Heading "Drag a vessel — watch the verdict update" + Body subhead, with the "Reset scenario" outline button (+ relocated Save/Share icon button per D-07/Pitfall S3) right-aligned on the same row.
2. Chip row: 6 pill buttons, single row, left-aligned, `gap-8px` (sm token) between chips.
3. Verdict banner: full-width `Card`, spans both columns of the grid below (confirmed via direct image inspection — this is **not** nested inside the reasoning column).
4. 2-column grid (`grid-cols-[minmax(0,3fr)_minmax(0,2fr)] gap-16px`): Chart (`ChartPanel`) in the left column; a `flex flex-col gap-16px` "reasoning column" in the right column containing, in order: Instrument-Readouts card (2×2 grid + status pill inside the same card, per direct image inspection — the status pill is **not** a separate card, it's the bottom element inside the Instrument-Readouts card), then the Reasoning-Trail card.
5. Full-width row below the grid: 2 vessel-control cards side by side (`grid-cols-2 gap-16px`).

**Below 900px (D-06, SBOX-05):** single column, stacked in this exact order: Chart → Reasoning column (Instrument Readouts + status pill, then Reasoning Trail) → Controls (2 vessel-control cards). Header row/chip row/verdict banner stay full-width above this stack unchanged.

**Below 640px (SBOX-05):** the 2 vessel-control cards additionally stack to a single column (`grid-cols-1`) instead of side-by-side.

## Typography

**All roles are unchanged from Phase 6/Phase 7** (SCAF-06 — reused, not redeclared). This is the first phase to give the **Heading** role (24px/600/1.25) a real instance — used **twice** this phase: once for the section heading, and again reused for the verdict banner title (see below). No 5th font-size is introduced; the 4-size ceiling has no semantic-justification escape valve, so the verdict banner title must reuse an existing role rather than carry forward its own distinct size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 13px | 600 | 1.4 |
| Body | 16px | 600 | 1.5 |
| Heading | 24px | 600 | 1.25 |
| Display | 52px | 800 | 1.1 | *(no Sandbox instance this phase — Hero-only)* |

Sandbox's concrete usage of these roles:

- **Eyebrow** ("Interactive sandbox · night-display mode"): Label role, 13px/600, Geist Mono, `--muted-foreground` (uppercase tracking, no accent dot this time — plain text, matches direct image inspection, distinct from Hero's dotted-badge eyebrow treatment).
- **Section heading** ("Drag a vessel — watch the verdict update"): Heading role, 24px/600/1.25, `--foreground`, single color (no two-tone split — that treatment is Hero-only).
- **Section subhead** ("Drag a hull to reposition it, grab the bow handle to change heading, and adjust speed & type below. Classification recomputes live."): Body role, 16px/600/1.5, `--muted-foreground`.
- **Chip labels**: Label role, 13px/600 (matches shadcn `Button` `sm` text treatment) — active chip white text (`--primary-foreground`-equivalent, sampled `#FFFFFF`) on solid rule-accent fill; inactive chips `--muted-foreground` (sampled `#A1A1AA`, matches existing token exactly) on `--card`/`--border` outline.
- **Verdict banner title** ("Crossing"): reuses the **Heading** role exactly — 24px/600/1.25, `--foreground` (same role/size as the section heading, not a new size). This changes `ReasoningPanel.tsx`'s current `text-[28px] font-semibold` class down to the Heading role's 24px equivalent (e.g. `text-2xl font-semibold leading-[1.25]`) — accept the small visual delta (28px → 24px) rather than carrying forward a 5th font-size; the "3-4 sizes" ceiling has no semantic-justification escape valve, so this reuse is mandatory, not discretionary. `Rule 15` chip: Label role 13px/600 on solid accent fill.
- **Verdict banner description** ("Vessel A gives way. Give-way vessel takes early, substantial action; stand-on vessel holds course and speed."): Body role, 16px/600 (wait: sampled slightly smaller in the mock, ~15px — treat as Body role 16px per the 4-size ceiling; do not add a 5th size for a 1px difference), `--muted-foreground`.
- **Role badges** ("Vessel A / GIVE WAY", "Vessel B / STAND ON"): 2-line stack — "Vessel A"/"Vessel B" label at Label role 13px/400-weight-equivalent (muted), "GIVE WAY"/"STAND ON" at Label role 13px/600 Geist Mono, uppercase, in the semantic role color (see Color below).
- **Instrument-readout tiles** (RANGE/BEARING A→B/CPA/TCPA): tile label Label role 13px/600 uppercase `--muted-foreground`; tile value reuses Hero's established **Body role, 16px/600, Geist Mono, `--foreground`** convention exactly (Phase 7 explicitly reserved this for Phase 8 — do not invent a separate "instrument-value" size).
- **Status pill**: Label role, 13px/600, colored per tone (see Color below), with a small solid dot (4px, xs token) leading the text.
- **Reasoning-trail numbers** (1/2/3 circles): Label role, 13px/600, white text on the step's tone color.
- **Reasoning-trail tags** (GEOMETRY/RULE 15/VERDICT): Label role, 13px/600, uppercase, tracked, colored per tone (see Color).
- **Reasoning-trail body text**: Body role, 16px/600 wait — sampled closer to 15-16px sans (not mono) `--foreground`/near-white — treat as Body role, 16px/600.
- **"3 steps" pill** (trail card header): Label role, 13px/600, `--muted-foreground`, outline pill.
- **Vessel control card header** (letter-chip "A"/"B" + "Vessel A"/"Vessel B" + role badge): letter-chip Label 13px/600 white-on-`--foreground` (light square swatch, dark text — matches direct image: a near-white square with dark "A"), heading text Body role 16px/600 `--foreground`, role badge Label 13px/600 pill (same role-color treatment as the verdict banner's badges, smaller pill).
- **Field labels** ("TYPE", "SPEED", "HEADING"): Label role, 13px/600, uppercase, `--muted-foreground`.
- **Speed value readout** ("12 kn"): Body role, 16px/600, Geist Mono, **`--primary`** (`#2dd4bf` — sampled exactly, confirms this is the app's existing brand accent, not the rule-accent teal below — see Color).
- **Heading value readout** ("035°", read-only, no new control): Body role, 16px/600, `--foreground` (not accent-colored — only the live-editable Speed value gets the accent treatment).
- **"1 NM" scale-bar legend**: Label role, 13px/600, Geist Mono, `--muted-foreground`, next to a short horizontal tick-mark line matching `--border`.

## Interaction Contract (supplementary — carried from CONTEXT.md/RESEARCH.md, restated here as the visual/interaction source of truth for the executor)

- **Chip row is a button group, not `Tabs`/`ToggleGroup`** (Pattern 2) — one-shot data-load action, not persistent tabbed content. Track `activeChipId` in `SandboxContainer` state; clear it (deselect all chips, no chip shows the active teal fill) on any manual drag/heading/speed/type-select change that doesn't originate from a chip click, so the highlight never goes stale/misleading.
- **Chip click = full replace + hysteresis reset**, mechanically identical to `handleReset()` (D-02) — no partial merge, no confirmation dialog, any in-progress drag is discarded silently.
- **Verdict banner is full-width**, spanning both grid columns, sitting above the chart/reasoning 2-col row (confirmed via direct image inspection, not the reasoning-column-only alternative).
- **Instrument-readouts and the status pill share one card** — the status pill is the last element inside the Instrument-Readouts `Card`, not a separate card of its own.
- **Reasoning-trail step count is dynamic** — never hardcode 3; render `classification.trail.length` steps, tag-mapped per the table above.
- **Heading stays read-only/drag-only** — no new editable heading form control is added; the vessel-control card's "HEADING" row is a plain read-out.
- **Hit-testing regression is the single highest-risk item this phase** — restyling `ChartPanel`'s hull/rotate-handle fill/stroke values must preserve `pointer-events: visiblePainted` semantics (non-`"none"` fill/stroke at every step); mandatory manual browser drag+rotate UAT before merging, per `PITFALLS.md` Pitfall 1 — jsdom tests cannot catch this class of regression.
