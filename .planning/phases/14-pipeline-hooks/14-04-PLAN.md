<!-- Pattern 2, research/ARCHITECTURE.md -- reused directly, not reinvented -->
Vercel (and Vercel-compatible hosts) auto-prefer a `"vercel-build"` package.json script over
the plain `"build"` script when present. Vercel sets `process.env.VERCEL_ENV` to one of
`"production"` / `"preview"` / `"development"` automatically at build time -- this is the
signal the gate must key off, since a PR/branch preview build runs the identical script with
`VERCEL_ENV="preview"` and must NEVER apply a migration to the live database.

Existing, unmodified scripts to preserve exactly as-is (CI depends on these, per plan 14-01):
- `"build": "next build --webpack"`
- `"postinstall": "prisma generate"` (added by plan 14-01)

Local verification substitutes the not-yet-provisioned production host with the same
`docker-compose.yml` Postgres CI already uses (`postgresql://colregs:colregs@localhost:5432/colregs_navigator?schema=public`,
matching `.env.example`) -- this is a legitimate stand-in only for confirming the *script's
own logic* (gating + command sequencing), not a claim that production DB behavior was
verified (that is explicitly Phase 15's job).
</interfaces>
