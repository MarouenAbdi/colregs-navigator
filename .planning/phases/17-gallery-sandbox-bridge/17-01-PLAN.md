Output: `SandboxBridgeProvider.tsx` (new), `app/page.tsx` and `app/s/[shareId]/page.tsx` both wrapping their `SandboxContainer` render in the Provider, and `SandboxContainer.tsx` consuming `useSandboxBridge()` to call the already-shipped `loadScenario()` (Phase 16) whenever a new scenario is requested.

```typescript
export type PendingScenario = { vesselA: Vessel; vesselB: Vessel; requestId: number };

export function SandboxBridgeProvider({ children }: { children: React.ReactNode }): JSX.Element;

export function useSandboxBridge(): {
  pendingScenario: PendingScenario | null;
  requestLoad: (vesselA: Vessel, vesselB: Vessel) => void;
};
```

`useSandboxBridge()` throws `new Error("useSandboxBridge must be used within SandboxBridgeProvider")` when called outside the Provider (standard React Context guard idiom, per ARCHITECTURE.md Pattern 2's own worked example). `requestId` is keyed off `Date.now()` in `requestLoad`, not vessel-pair object identity, so re-selecting the same scenario twice in a row still re-triggers the effect.
</interfaces>
