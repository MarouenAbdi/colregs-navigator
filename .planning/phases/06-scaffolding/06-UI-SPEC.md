## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (e.g. Source button icon↔text, logo icon↔wordmark gap) |
| sm | 8px | Compact spacing between Header/Footer inline elements (chip↔wordmark, nav link gaps) |
| md | 16px | Default padding inside Header/Footer content row, gap between Footer's two text blocks on narrow viewports |
| lg | 24px | Horizontal page-gutter padding on Header/Footer content container (desktop) |
| xl | 32px | Horizontal page-gutter padding on Header/Footer content container (wide desktop, ≥900px) |
| 2xl | 48px | Reserved for major section breaks in later phases (Hero/Sandbox/Gallery) — not directly consumed by Header/Footer chrome itself |
| 3xl | 64px | Sticky **Header height** (`h-16` equivalent) — also drives `scroll-padding-top: 64px` on the scroll container per CONTEXT.md D-06, so future `#sandbox`/`#gallery` anchor targets never land underneath the sticky header |

Exceptions: none. The Header collapses to Logo + "Source" button only below 640px (CONTEXT.md D-03) via a Tailwind responsive-hide utility on the "Sandbox"/"Gallery" anchor links — no new interactive component (no hamburger, no drawer, no icon-only 44px touch target introduced).

## Typography

Pre-populated from `.planning/design/claude-design-prompt.json` ("current_baseline: ... Only two weights used: 400 and 600") and measured against `.planning/design/Main-Design.png`. This is the **shared, app-wide type scale** — Scaffolding defines it once in `app/globals.css`/Tailwind theme; Hero/Sandbox/Gallery consume these same 4 roles rather than declaring their own sizes (SCAF-06).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 13px (Geist Mono for numeric/instrument text, Geist Sans for nav/UI labels) | 600 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 24px | 600 | 1.25 |
| Display | 48px | 600 | 1.15 |

Phase 6's own usage of these roles:
- **Header wordmark** ("COLREGS Navigator"): Heading role, but rendered at a smaller in-context size within the sticky bar — use `text-base`/16px equivalent at weight 600 for "COLREGS", weight 400 for "Navigator" (matches the two-tone weight treatment visible in the design), not the full 24px Heading size (that's reserved for in-page section titles like Sandbox's "Drag a vessel — watch the verdict update").
- **Header "Rules 11-18" chip, nav links ("Sandbox"/"Gallery"), "Source" button label**: Label role, 13px/400 (nav links are not mono, only true instrument-style numeric readouts use Geist Mono — nav/UI labels stay in Geist Sans at the same 13px size).
- **Footer content** (both text blocks — brand line and disclaimer line): Label role, 13px/400, muted foreground color.
- **Display and full 24px Heading roles** are declared here as shared tokens but have no Phase-6-owned instance (Display = Hero's headline, Phase 7; 24px Heading = Sandbox/Gallery section titles, Phases 8/9) — declaring them now satisfies SCAF-06's "one shared location" requirement so downstream phases don't redefine sizes independently.

## Color

Base palette pre-populated from `REQUIREMENTS.md` SCAF-02 (locked) and `.planning/research/ARCHITECTURE.md` Pattern 2 (dark-only, no `.dark` toggle, no `next-themes`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#09090B` (Tailwind zinc-950-equivalent base) | Page `<body>` background, Header/Footer background (same as page — chrome is not visually separated from content by a different surface color) |
| Secondary (30%) | Zinc scale — `#18181B` (zinc-900) for elevated surfaces (Cards, panels built in later phases); `#27272A` (zinc-800) for borders/dividers, including the Header's bottom hairline border and Footer's top hairline border | Card/panel surfaces (Hero preview card, Sandbox panels, Gallery cards — Phases 7–9); Header/Footer separator borders (this phase) |
| Accent (10%) | `#2dd4bf` (teal-400-equivalent) | Reserved for: focus rings on interactive elements (nav links, Source button, any `Input`/`Select`/`Button`), active/hover state of Header nav links, the teal portion of the Hero headline ("See who gives way — and why.", Phase 7), live-indicator dots, active tab/rule badges (Phase 8/9). **Not used** for Header/Footer static text, borders, or decorative fills in this phase — Phase 6's own accent usage is limited to focus-visible rings and nav-link hover/active state. |
| Destructive | shadcn default destructive red (`--color-destructive`, register per shadcn `radix`/`nova` preset default) | Not exercised by any Phase 6 UI (no destructive actions in Header/Footer/shell) — token is registered now as part of the shared theme so Sandbox's "Reset scenario" (a non-destructive reset, uses standard button, not this token) and any future confirmation flow can consume it without re-declaring |

Accent reserved for: focus-visible rings, nav-link hover/active underline or color shift, and (in later phases) primary CTA fills, live-state indicators, and active-tab/rule-badge accents. Never used for body copy, panel backgrounds, or borders.

Domain-semantic colors (give-way red `#EF4444`, stand-on green `#22C55E`, mutual slate `#94A3B8`, doubt amber `#F59E0B` dashed, bearing-line slate `#475569`) are **locked** per `claude-design-prompt.json` and out of scope for this phase — they belong to the Sandbox restyle (Phase 8) and must not be redefined or touched here. Scaffolding's job is only to register the chrome palette (dominant/secondary/accent above) under Tailwind v4's `@theme`/`@theme inline`, per Pitfall 3/4.

## Executor Notes (supplementary — not template-required, carried from upstream research)

- **Dark-only render check (Pitfall 2):** After wiring the theme, verify the app renders dark with the OS/browser color-scheme preference set to **light**. `<html>` must carry a permanent `className="dark"` (or the `:root`/`.dark` split must be deliberately collapsed to one palette) — no `next-themes`, no toggle UI, no half-wired machinery.
- **`scroll-padding-top` (D-06):** Set to the Header's actual rendered height (64px per the Spacing Scale above) on the scroll container, in this phase — not deferred to Phase 7/9.
- **Logo icon (Claude's Discretion, CONTEXT.md):** Exact `lucide-react` icon for the logo mark is not locked by this contract — pick the closest visual match to the small circular glyph in `Main-Design.png`'s header (candidates: `Compass`, `Navigation`, `LocateFixed`) during planning/implementation, per CONTEXT.md's explicit deferral.
- **Commit-first discipline (Pitfall 7):** Commit the working tree before running `npx shadcn@latest init` or any `shadcn add`; diff-review `globals.css`/`components.json` afterward to confirm no existing custom breakpoints (900px/640px, defined by later phases but must not be clobbered if already present) were dropped.
