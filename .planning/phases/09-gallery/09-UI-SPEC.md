## Visual Focal Point

**Primary visual anchor:** the centered section heading ("Classic encounters, one click away") — larger and bolder than any other in-section-body heading in the app except Hero's own Display headline, it closes the page with the same confident weight Hero opened it with. **Secondary anchor:** the 6-card grid itself, specifically each card's mini-chart illustration — it is a miniature echo of the live Sandbox above it, which is the exact visual cue that reinforces "click to load this into the sandbox." The Rule-N/role-verdict badge row and title are the third read (confirms *which* classic encounter before committing to a click); the one-line description is quietest, confirmatory text only. No element in this section should visually compete with the Sandbox's own verdict banner above it — Gallery is deliberately a smaller-scale, denser echo, not a second hero moment.

## Layout

**Section container** (reuses the exact container convention already shipped in `SandboxContainer.tsx` — do not invent a new one): `mx-auto max-w-300 px-5 py-12 min-[900px]:px-6 min-[900px]:py-16`.

**Header block** (eyebrow + heading + subhead) — **centered**, not left-aligned like Hero/Sandbox's headers (confirmed by direct image inspection, a deliberate deviation for this closing section): `flex flex-col items-center gap-3 text-center`, `mb-8 min-[900px]:mb-12` before the card grid. Subhead is width-constrained (`max-w-125` / 500px, `mx-auto`) to preserve its 2-line wrap.

**Card grid** — 3 → 2 → 1 columns (GAL-01), reusing this project's existing 640px/900px breakpoints (no new breakpoint token, per CONTEXT.md's discretion item — Claude's Discretion is resolved: reuse, do not invent a third breakpoint):

```
grid grid-cols-1 gap-4 min-[640px]:grid-cols-2 min-[900px]:grid-cols-3
```

**Correction to 09-RESEARCH.md's Grid Breakpoints section:** research recommended `gap-6` (24px) as a MEDIUM-confidence, non-pixel-verified guess. Direct pixel measurement of `Main-Design.png`'s 3-column desktop row (card-to-card gap measured both horizontally and vertically, independently, both resolving to the same value) gives **16px**, not 24px. Use `gap-4`, not `gap-6`. (Measurement: at a 2880px-canvas/1440px-viewport 2× export, card-to-card background gap = 32 canvas px = 16 logical px, both axes.)

**Per-card layout:** `<Link href="/s/{scenario.id}">` wrapping a `Card` with **zero internal `CardHeader`/`CardContent` split needed** (single padded column): mini-chart box (full card width, fixed 3:2 aspect ratio, `mb-4`) → badge row (`Rule {N}` outline badge left, verdict role badge right, `flex items-center justify-between`, `mb-3`) → title (`<h3>`, `mb-1.5`) → description (2-line paragraph). Card internal padding: **16px on all sides** (`p-4`) — this is the already-declared `md` token from the Spacing Scale below (the same token used for the grid gap), not a new value.

## Typography

**Label and Body roles are unchanged from Phase 6/7/8** (SCAF-06 — reused, not redeclared). **Heading role is reused at its exact existing 24px value for card titles.** **Display role gets a new, phase-specific concrete instance** (see Correction note) — this is the only size in this table that is not a byte-identical reuse of an already-shipped value.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 13px | 600 | 1.4 |
| Body | 16px | 600 | 1.5 |
| Heading | 24px | 600 | 1.25 |
| Display | **36px** (this phase's instance — see Correction note) | **700** | 1.15 |

**Weight resolution (2-weight maximum, this phase's own scope):** 600 (Label, Body, Heading — all reused) and 700 (Display, this phase's section heading only). This is a deliberate, smaller step than Hero's 800 (Hero's Display is the app's single loudest moment; Gallery's is a closing section heading, one register down) — not a copy-paste of Hero's weight, a considered choice.

**Correction note (Display role, this phase's instance):** Direct pixel measurement of `Main-Design.png`'s "Classic encounters, one click away" heading (cap-height measured independently at two different crops, cross-calibrated against both Hero's already-locked 52px Display instance and this phase's own 24px card-title measurement for consistency) resolves to **~36-39px**, not 24px (Sandbox's Heading-role instance) and not 52px (Hero's Display instance). This sits *between* the two already-declared roles — too large to "accept the small delta" and reuse Heading (a ~50% size gap, well beyond the ~15-20% deltas Phase 7/8 accepted), but distinctly smaller than Hero's own Display instance. Resolution: this is filed as **this phase's own concrete instance of the Display role** (the app's "largest, boldest heading on the page" tier), at a phase-specific 36px/700 rather than Hero's 52px/800 — analogous to how Hero's Display already varies by breakpoint via `clamp()`; here it varies by *section* instead. Do not introduce this as a 5th independently-named role — it is Display, used a second time, at a different concrete size, exactly as Heading was already reused twice within Phase 8 (Sandbox heading + verdict banner title) at the *same* size. Card titles ("Classic crossing" etc.) independently pixel-measure to ~23-24px, confirming they ARE Heading-role reuse (no correction needed there).

Gallery's concrete usage of these roles:

- **Eyebrow** ("Curated scenarios"): Label role, 13px/600, Geist Mono, `--primary`/`--accent` (teal) color, **plain text, no pill/badge border** (confirmed by direct image inspection — matches Sandbox's plain-text eyebrow treatment, not Hero's dotted-badge-pill treatment), centered, mixed-case (not forced uppercase).
- **Section heading** ("Classic encounters, one click away"): Display role, 36px/700/1.15, `--foreground` (white), single color — no two-tone split (that treatment is Hero-only), centered.
- **Section subhead** ("Textbook COLREGS geometries. Load any into the sandbox and drag from there."): Body role, 16px/600/1.5, `--muted-foreground`, centered, width-constrained to preserve its 2-line wrap.
- **Card Rule-N badge** ("Rule 15" etc.): Label role, 13px/600, Geist Mono, `--primary`/`--accent` (teal) **outline** treatment (`Badge variant="outline"` with `text-accent`/`border-accent` — see Color section; pixel-sampled `#2DD3BE`, an exact match to `--primary` `#2dd4bf`, confirming this reuses Hero's eyebrow-badge outline convention, **not** Sandbox's solid rule-accent chip convention).
- **Card verdict role badge** ("A GIVES WAY" / "MUTUAL", right-aligned in the same row as the Rule-N badge): Label role, 13px/600, Geist Mono, uppercase — colors/tint via the existing `ROLE_BADGE_CLASSNAME` (`vessel-role.ts`) give-way/mutual variants (see Color section). Text is `"{VESSEL_LABEL} GIVES WAY"` or `"MUTUAL"`, not the 2-letter `ROLE_BADGE_TEXT` abbreviations (those are reserved for the mini-chart's per-vessel pill — see below).
- **Card title** ("Classic crossing" etc.): Heading role, 24px/600/1.25 (reused byte-identical to Sandbox's Heading instance), `--foreground`, semantic `<h3>` (the section heading above is the page's `<h2>`).
- **Card description** (one-line-wrapping-to-two sentence): Body role, 16px/600/1.5 (reused — matches Phase 8's own precedent of "measured slightly under 16px, still classified as Body role, accept the small delta" for its verdict-banner description), `--muted-foreground`.
- **Mini-chart vessel circle labels** ("A"/"B"): SVG-native, not a Tailwind text class — reuse Hero's exact `fontSize={10} fontWeight={600}` white-on-`#18181B`-circle convention (`HeroPreviewCard.tsx`'s `VesselMarker`), unchanged.
- **Mini-chart per-vessel role pill** ("GW"/"SO"/"MU"): SVG-native, reuse Hero's exact `fontSize={7.5} fontWeight={600}` white-text-on-solid-role-color-fill convention, **with one required change**: the pill-text map must be **local to `GalleryPreviewChart.tsx`**, `{ "give-way": "GW", "stand-on": "SO", mutual: "MU" }` — do **not** reuse `vessel-role.ts`'s `ROLE_BADGE_TEXT.mutual` ("MUTUAL", 6 characters) for this small pill; it will overflow/wrap at this scale (see 09-RESEARCH.md Pitfall 3, confirmed correct by direct pixel inspection of all 4 mutual-role pills in the design).
- **Mini-chart range-label chip** ("5.03 NM" etc.): SVG-native, reuse Hero's exact `fontSize={12}` mono, `#D4D4D8` text on `#18181B` fill / `#27272A` border chip, unchanged.

## Mini-Chart Contract (`GalleryPreviewChart.tsx`)

**This section is the primary correction to both CONTEXT.md's D-07 and 09-RESEARCH.md's Pattern 2** — both were produced from a coarser full-page pass; this UI-SPEC's pixel crop-and-zoom of the mini-chart's actual interior (not just its surrounding card) surfaces one further correction beyond research's own already-noted "dashed heading vectors ARE present" fix.

**Element set (every card, confirmed present, in z-order back to front):**
1. **A faint grid pattern fills the chart box background** — contrary to 09-RESEARCH.md Pattern 2's claim of "no grid pattern," direct pixel crop-and-zoom of the chart interior (not just the card shell) shows a clear, regular ~20-22px-period grid, visually identical in technique to Hero's own `heroGrid` SVG pattern, just fainter (measured stroke opacity ≈8-10%, vs. Hero's declared 14% — i.e., reuse Hero's `<pattern id="...">` grid technique at a **lower opacity**, not a differently-authored pattern). **No range rings, no radial gradient bearing sector** — those two Hero elements are confirmed absent (research's original correction stands).
2. Thin solid connector/bearing line between the two vessels (`--color-geometry` / `#475569`, matches Hero's `CONNECTOR_STROKE`).
3. Two hull triangles, **role-colored** (not vessel-slot-colored — give-way red `#EF4444`, stand-on green `#22C55E`, mutual slate `#94A3B8`; every hull/badge color decision must derive from `getVesselRole()`, never a hardcoded per-slot constant — see Pattern 3 in 09-RESEARCH.md, confirmed correct by this UI-SPEC's own pixel sampling of the mutual-role cards).
4. Dark circular label badge ("A"/"B") floating above each hull, non-rotated (matches Hero's `VesselMarker` grouping — hull rotates with heading, label/pill groups do not).
5. Solid-fill, role-colored 2-letter pill ("GW"/"SO"/"MU") below/beside each hull.
6. Dashed heading-vector line from each hull, stroked in that vessel's role color (not a fixed per-slot color — same correction as item 3).
7. A floating range-label chip ("X.XX NM") at the connector line's midpoint.

**Chart box dimensions:** fixed **3:2** aspect ratio (width:height), directly pixel-measured (358px : 238px logical, ≈1.50), a correction to Hero's own 8:5 (1.6) ratio — Gallery's mini-chart is proportionally slightly less wide/more square than Hero's. Full card width (card width minus 2×16px padding), height derived from the 3:2 ratio.

**Per-card dynamic viewBox:** reuse 09-RESEARCH.md's `computeCardViewBox()` recommendation (Pattern 1) unchanged — a fixed Hero-style hand-solved viewBox cannot work here since the 6 cards' real vessel-pair ranges span 1.0-10.0 NM. Bounding-box-of-both-vessels + padding fraction, forced to the 3:2 aspect ratio.

**Chart box surface color:** reuse the already-registered `--color-chart-surface` token (`#0B0B0E`, added Phase 8) rather than a new hardcoded hex or Hero's separate literal `#0B0B0E` inline value — `bg-chart-surface`, satisfying SCAF-06.

**Hull path/stroke, heading-vector-endpoint math, midpoint math:** reuse Hero's existing `HULL_PATH`/`HULL_STROKE`/`HULL_STROKE_WIDTH`/`headingVectorEndpoint()`/`midpoint()` exactly (extraction to `src/components/shared/static-chart-geometry.ts` recommended per 09-RESEARCH.md's extraction proposal — Gallery is a genuine second consumer, satisfying this project's "extract only on a real second consumer" convention).

## Interaction Contract (supplementary — carried from CONTEXT.md/09-RESEARCH.md, restated as this phase's visual/interaction source of truth)

- **Whole-card click target, not a labeled button:** `<Link href="/s/{scenario.id}">` wraps the entire `Card`. Add `aria-label="Load {title} scenario into the sandbox"` on the `Link` (the card's visible text already conveys this, but the wrapped `Card`'s internal heading/badges could otherwise read ambiguously to a screen reader as a bare link).
- **Hover state (not shown in the static design — this phase's own addition, restrained per `claude-design-prompt.json`'s "instrument-panel smoothness, not playful bounce" motion philosophy):** on hover/focus, transition the card's `border-border` to `border-primary/40` and apply a subtle `bg-card/80`→`bg-card` or 1px lift via `shadow-sm`, `transition-colors duration-200`. Add a visible `focus-visible:ring-2 focus-visible:ring-ring` for keyboard navigation (the whole card is now a single large focusable link — this is a real accessibility requirement, not decorative). Do **not** animate/rotate the mini-chart's hulls or lines on hover — motion stays restrained to the card chrome only, matching the "restrained... reinforce precision, not decorate" philosophy.
- **GAL-02 wiring is unchanged from the existing `/gallery` route:** plain `<Link href="/s/{scenario.id}">`, no client-side state lift, no `onClick` handler beyond the implicit navigation — `app/s/[shareId]/page.tsx` (already server-rendered, pre-seeds `SandboxContainer`) is the unchanged destination.
- **Server-rendered, not client-fetched (GAL-04):** `GalleryContainer.tsx` is an `async` Server Component (`await getCaller().gallery.list()`), matching the current `app/gallery/page.tsx` pattern exactly — this is a hard visual/architectural requirement, not a style preference, since `id="gallery"` must exist at first paint for the `/gallery` → `/#gallery` redirect's scroll-to-anchor behavior to work.
