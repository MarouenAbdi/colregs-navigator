## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing (trail step-card padding top: `16px 15px 15px`) |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (matches locked Header height, `app/globals.css` `scroll-padding-top`) |

**Exceptions (design-fidelity pixel values — reproduce `20-DESIGN-SNAPSHOT.md` verbatim, not derived from the 8pt scale):**
This codebase has an established precedent (`hero-preview-geometry.ts`'s header comment: "reproduce its exact layout, not eyeballed") of hand-typing the design source's literal pixel values rather than rounding to the 8pt scale, wherever the design snapshot specifies an exact number. This phase's exceptions:
- Trail step card: `border-radius: 13px`; padding `16px 15px 15px`; connector segment `flex: 0 0 34px`; connector height `3px`; connector dash cycle `11px` (`5px` dash / `6px` gap); traveling-pulse dot `6px` diameter; step token `38px` diameter; corner brackets `11px × 11px`, `1.5px` border; header radar-sweep-dot variant `14px` (vs. the existing `.radar-sweep-dot` base `8px`).
- Trail responsive breakpoint: `900px` (`min-[900px]:` — already this codebase's convention, see `SandboxContainer.tsx`/`ChartFooterStrip.tsx`); below it, connector band shrinks to a fixed `26px`.
- Hero bezel (320×200 viewBox, 8:5 aspect, unchanged): 3 range rings at `28px` / `56px` / `84px` radius (half-width 160px × `.175`/`.35`/`.525`, scaled down from the design's 42/84/126-on-480 canvas ratios); compass-tick ring at `88px` radius (160px × `.55`); minor-tick `stroke-width 5`, `dasharray "1.5 9.42"`; major-tick (cardinal) `stroke-width 9`, `dasharray "3 66.13"`.
- Hero radar-sweep overlay: `47.9%` of container width, `aspect-ratio: 1`, centered via `translate(-50%,-50%)`.
- Animation durations (all CSS-only, see Motion Contract below): `conduit 0.55s`, `travel 1.9s`, per-token `sweep`/`.radar-sweep-dot` rotation `2s` (existing) or a distinct duration for the trail header's `--lg` variant if visually needed, Hero radar-sweep `4.5s`, Hero LIVE-dot pulse `2.8s` (locked below, distinguishing it from Sandbox's `2s` `animate-pulse`).

None of these are new conventions — they extend the same "reproduce the design source's literal numbers" pattern already used by every prior chart/strip component in this codebase (`ChartHeaderStrip.tsx`, `ChartFooterStrip.tsx`, `hero-preview-geometry.ts`).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro label (mono, tracked, uppercase — contact labels, tile labels, tags) | 9.5px | 600 (semibold) | 1.2 |
| Body (secondary/muted text, fact readouts, footer role-action text) | 12.5px | 400 (regular) | 1.5 |
| Value / readout (mono — RANGE/BEARING/CPA/TCPA values, rule badges) | 15px | 600 (semibold) | 1.2 |

**Declared working weights for this phase: 400 (regular) and 600 (semibold) — 2 weights only.** This is the complete type-scale contract this phase is accountable for; no role above requires or introduces a third weight.

**Out-of-scope legacy usage (excluded from this phase's declared type scale, not a 3rd weight):** The header-strip title (e.g. "Crossing", "Head-on") renders at 18px (`text-lg`) / weight 700 (`font-bold`) — this markup is inherited byte-for-byte and unmodified from Phase 18's `ChartHeaderStrip.tsx`. This phase's Hero header strip mirrors that existing component per D-03 without touching its size, weight, or line-height in any way. It is noted here purely for traceability (so a reviewer knows the 700-weight text on screen is pre-existing, not new); it is not a role this phase declares, modifies, or is graded against under Dimension 4.

Font-size micro-variance note: exact sizes in the shipped components range from 8.5px (contact label) to 17px (footer tile value) — the three roles above are the load-bearing categories this phase touches; do not introduce a fourth arbitrary size not derivable from one of these three roles or the Exceptions list above.

## Motion Contract

*(Addendum to the standard template — this phase's success criteria are animation-heavy per D-05/D-06; called out explicitly since the checker's Visuals dimension needs a concrete, not exploratory, spec.)*

All animations below are CSS-only (`@keyframes` in `app/globals.css`, class-toggle-only in components, per CLAUDE.md's "no raw CSS composed as strings" rule and the project's `getBoundingClientRect()`/`getBBox()` ban). Every animation MUST be wrapped in `@media (prefers-reduced-motion: no-preference)` (D-06); the reduced-motion fallback is a **fully static equivalent** (no animation property applied at all — matches the existing `.radar-sweep-dot` precedent), not a single non-repeating transition.

| Layer | Where | Keyframe | Duration/Timing | Effect |
|-------|-------|----------|------------------|--------|
| Connector dash flow | Trail `cwire` | `conduit` | `0.55s linear infinite` | `background-position: 0 → 22px` |
| Traveling pulse dot | Trail `cwire` | `travel` | `1.9s ease-in-out infinite` | `left: -4px → 100%+4px`, `opacity: 0→1→1→0` at 0/12/88/100% |
| Per-token radar sweep | Trail step token (38px) | new `.trail-token-sweep-ring` (own class, references `@keyframes radar-sweep`, per RESEARCH.md Open Question 2) | `2s linear infinite` (reuse existing `radar-sweep` keyframe) | `transform: rotate(0→360deg)` |
| Header radar-sweep dot | Trail header (14px) | `.radar-sweep-dot--lg` (size variant of existing `.radar-sweep-dot`, per RESEARCH.md Code Example) | `2s linear infinite` (inherits existing `.radar-sweep-dot` timing, only size changes) | Same conic-gradient spin, larger |
| Hero radar-sweep overlay | Hero chart, absolutely positioned over SVG | `sweep` (new) | `4.5s linear infinite` | `transform: rotate(0→360deg)`, `mix-blend-mode: screen`, `conic-gradient(from 0deg, rgba(45,212,191,.3), rgba(45,212,191,0) 60deg, transparent)` |
| Hero LIVE dot pulse | Hero footer strip | `.hero-live-pulse` (new, distinct from Tailwind's `animate-pulse` used by `ChartFooterStrip.tsx`) | `2.8s ease-in-out infinite` (slower than Sandbox's `2s`) | `opacity: .35 → .85 → .35` (dimmer floor/peak than Tailwind `animate-pulse`'s `.5→1`) |

**Hero LIVE dot color/class contract (resolves D-02, locks the two Claude's-Discretion items from CONTEXT.md):**
- Color: `bg-primary` (`#2dd4bf`) — NOT `bg-rule-accent` (`#0D9488`, the real Sandbox's color). Distinguished by hue/lightness alone, reinforced by the slower/dimmer pulse above.
- Class: new `.hero-live-pulse`, never the shared Tailwind `animate-pulse` utility (which is reserved for the real Sandbox's `ChartFooterStrip.tsx` LIVE dot).
- Reduced-motion fallback: static dot at a fixed mid-range opacity (`.6`), no animation.

**Layout-stability contract (resolves RESEARCH.md Pitfall 3, guards Phase 7's D-01 rationale):** The Hero SVG `viewBox` stays `0 0 320 200` (unchanged, 8:5) — the 3rd range ring, compass-tick ring, cardinal labels, and range labels must all fit within this existing viewBox, not force it larger. The footer strip growing from 3 tiles to 5 items (LIVE + RANGE/BEARING/CPA/TCPA) must not visibly increase the card's total rendered height in a way that shifts the `/#gallery` anchor scroll position — human-verified per Roadmap criterion 4.
