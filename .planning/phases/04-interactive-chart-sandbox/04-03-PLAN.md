|----------|-------------|
| Pointer input -> useHullDrag/useRotateHandleDrag -> ChartPanelProps callbacks | Untrusted screen-coordinate values cross into chart-space `Position`/heading numbers here, then are forwarded up to `SandboxContainer` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-09 | Tampering | `useHullDrag`/`useRotateHandleDrag` pointermove-derived numeric values | accept | this plan's hooks only forward drag-derived `Position`/heading values via `onVesselPositionChange`/`onVesselHeadingChange` callback props; they do not persist or trust this data themselves -- the actual `VesselSchema` validation boundary is `SandboxContainer.applyVesselUpdate` (04-06's T-04-01) |
| T-04-10 | Denial of Service (client-side) | high-frequency `pointermove` re-renders during continuous drag | accept | `classifyEncounter()`/`chartToScreen()`/`resolveDoubtGeometry()` are all pure synchronous trig with no I/O or unbounded loops; not adding throttling is a deliberate CHRT-02 requirement, not an oversight (04-RESEARCH.md Anti-Patterns) |
</threat_model>
