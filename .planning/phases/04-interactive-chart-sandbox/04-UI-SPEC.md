# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (decision — see rationale below) |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 components |
| Icon library | none — inline SVG glyphs only (reset arrow, doubt/warning triangle; 2 icons max) |
| Font | System UI sans stack (Tailwind `font-sans` default: `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, Helvetica Neue, Arial`) for all UI text. `font-mono` (Tailwind default monospace stack) for numeric geometric readouts (bearing°, speed kn, distance) so digits align in tabular columns. |

**shadcn decision rationale:** `components.json` not found; tech stack is Next.js/React so the shadcn gate applies. However, initializing shadcn requires an external interactive step (visit ui.shadcn.com/create, configure a preset, paste the string back) not available in this single-shot research pass. Neither CLAUDE.md's exhaustive locked-stack research nor 04-CONTEXT.md/04-RESEARCH.md mention shadcn anywhere, despite CLAUDE.md justifying every other dependency choice explicitly — a strong signal it was deliberately not selected. This phase's UI surface is small (one numeric speed input, one vessel-type select, one reset button) sitting alongside a hand-rolled SVG chart that is the actual design-effort center per D-05 (minimal/schematic, no decorative chrome). Revisit before Phase 5 (gallery + save/share) if that phase's larger form/list/card surface area would benefit more from a component library.

**Visual hierarchy:** The Display-size verdict banner (28px/600, top of the reasoning panel — e.g. "Crossing — Vessel A gives way") is the primary visual anchor on the sandbox screen; the chart's color-coded vessel hulls are the secondary anchor, reinforcing the same verdict spatially. Everything else (form controls, trail detail entries, grid) is tertiary and intentionally understated per D-05's minimal/schematic chart style — the eye should land on "what's the verdict" before "what are the exact numbers."

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding |
| sm | 8px | Compact element spacing (form field internal padding, trail entry internal gap) |
| md | 16px | Default element spacing (between form fields, trail entries) |
| lg | 24px | Section padding (inside ChartPanel/ControlPanel/ReasoningPanel cards) |
| xl | 32px | Layout gaps (between the three main panels) |
| 2xl | 48px | Major section breaks (page header to panel grid) |
| 3xl | 64px | Page-level spacing (outer page padding on desktop) |

Exceptions:
- **Rotate-handle hit target:** visible handle renders at `r=6px` (screen pixels, per RESEARCH.md Pitfall 2 — size in screen px, not chart units, to avoid non-uniform-scale ellipse distortion), but the invisible pointer-capture hit-circle is `r=22px` (44px diameter) to meet WCAG 2.5.5 AA minimum touch target size. This refines RESEARCH.md's `r=14` suggestion up to the accessibility minimum — RESEARCH.md flagged the general small-target pattern but did not check WCAG target size explicitly.
- **Hull drag hit target:** the vessel hull polygon itself must have a minimum bounding hit area of 44x44px on screen; if the rendered hull is visually smaller at typical zoom, pad with an invisible transparent hit-shape matching the hull's outline, not a plain circle (so it doesn't overlap the rotate-handle's own hit-circle).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Usage:
- **Body (16px/400):** reasoning trail entry text, form helper text, doubt caveat line.
- **Label (14px/600):** form field labels ("Speed (kn)", "Vessel type"), rule-ID badges in the trail ("Rule 15"), vessel role badges ("GW" / "SO" / "MUTUAL").
- **Heading (20px/600):** panel titles ("Reasoning Trail", "Vessel A", "Vessel B").
- **Display (28px/600):** the current verdict banner at the top of the reasoning panel (e.g. "Crossing — Vessel A gives way").
- **Numeric readouts** (bearing, speed, distance values) use `font-mono` at the Body/Label size they appear in, per the Design System font rule above — never Display size for raw numbers.

Only 2 weights declared (400, 600) — no light/bold/black variants anywhere in this phase.

## Color

Two color systems apply to this phase: standard app-chrome colors (60/30/10, this section) and domain-semantic overlay colors that are locked by CONTEXT.md decisions and must never collide with app chrome (next section).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `slate-50` `#F8FAFC` | Page background |
| Secondary (30%) | `white` `#FFFFFF` (surface) + `slate-200` `#E2E8F0` (border/grid) | ChartPanel, ControlPanel, ReasoningPanel card surfaces; chart's subtle grid lines (D-05) |
| Accent (10%) | `teal-600` `#0D9488` | Reserved for: primary CTA button (Reset Scenario), focus/active outline on form inputs, hover state on the rotate-handle, N-up heading label text |
| Destructive | not used this phase | No destructive actions exist in this phase (see Copywriting Contract). `red-600` `#DC2626` is explicitly NOT used for any UI chrome here — `red` is already claimed by the give-way hull semantic below and reusing it for chrome would create a false "danger" signal on a neutral action. |

Accent reserved for: Reset Scenario button, focus rings on the speed input / vessel-type select, rotate-handle hover/active stroke, N-up compass label text. Never used for hull fills, bearing lines, or doubt overlays — those are domain-semantic colors below, kept deliberately separate from brand accent so the verdict signal is never confused with generic "interactive element" styling.

### Domain Semantic Colors (Chart Overlay — locked/resolved from CONTEXT.md D-02/D-04)

| Role | Value | Usage |
|------|-------|-------|
| Give-way hull | `red-500` `#EF4444` | Vessel hull fill when `result.giveWay === <this vessel>` (D-02, locked) |
| Stand-on hull | `green-500` `#22C55E` | Vessel hull fill when `result.standOn === <this vessel>` (D-02, locked) |
| Mutual-obligation hull | `slate-400` `#94A3B8` | Both `giveWay`/`standOn` are `null` (head-on mutual-obligation case, RESEARCH.md's uncovered-case finding) — deliberately NOT amber, to avoid competing with the doubt overlay signal per D-04's own rationale |
| Doubt overlay | `amber-500` `#F59E0B`, dashed stroke (`stroke-dasharray: 4 3`) | Relative bearing line or overtaking boundary arc when `result.doubt === true` (D-04, locked) — reserved exclusively for doubt; never reused for hull fill |
| Bearing line (normal) | `slate-600` `#475569`, solid stroke, 2px | Relative bearing line overlay when no doubt is active |
| Overtaking boundary arc (reference) | `slate-300` `#CBD5E1`, solid stroke 1px, 10% fill opacity | Static reference wedge, always faintly rendered; swaps to amber/dashed only when `doubtBoundary === 'near-overtaking-crossing-boundary'` |

Resolves CONTEXT.md's two open "Claude's discretion" color items: the mutual-obligation hull color (slate, not amber — avoids the exact visual competition D-04 warns against) and the colorblind secondary cue (see Copywriting Contract badges below — color is never the sole signal for give-way/stand-on/mutual/doubt).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Reset Scenario** — button that restores both vessels to the D-06 default classic-crossing encounter. Non-destructive (client-only in-memory state, no persisted data exists yet in this phase — Phase 5 owns persistence). |
| Empty state heading | Not applicable — the chart always loads with a populated default scenario (D-06); there is no zero-vessel empty state in this phase. |
| Empty state body | Not applicable (see above). |
| Error state | Heading: **"Unable to classify"** / Body: **"Vessel A and Vessel B are at the same position — drag one apart to resume live classification."** Covers RESEARCH.md Pitfall 5 (`!result.ok`, coincident-position mid-drag). The chart and reasoning panel keep showing the last-good classification underneath this inline note rather than going blank. |
| Destructive confirmation | None in this phase — Reset Scenario is the only "reset-like" action and needs no confirmation dialog (ephemeral client state, instantly reversible by dragging again). |

### Additional copy elements specific to this phase (beyond template's generic slots)

| Element | Copy |
|---------|------|
| Doubt caveat — near-overtaking-crossing-boundary | "Near the overtaking/crossing boundary (112.5° abaft the beam) — this verdict may flip with a small heading change." |
| Doubt caveat — near-head-on-boundary | "Near the head-on boundary (reciprocal heading) — this verdict may flip with a small heading change." |
