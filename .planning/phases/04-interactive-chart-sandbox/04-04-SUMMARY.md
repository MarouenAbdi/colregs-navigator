### Auto-fixed Issues

**1. [Rule 3 - Blocking] Missing `node_modules` and generated Prisma client in the worktree**

- **Files modified:** none (installs generated artifacts only, gitignored)
- **Verification:** `npx tsc --noEmit` then passed cleanly
- **Committed in:** n/a (no source changes; environment setup only)

**2. [Rule 3 - Blocking] RTL automatic cleanup not registered between tests**
- **Found during:** Task 2 (writing/running ControlPanel tests)
- **Issue:** `vitest.config.ts` sets `globals: false` project-wide; `@testing-library/react`'s automatic `afterEach`-cleanup detection relies on a global `afterEach`, which never registers under this config. Without cleanup, later `it` blocks' `getAllByLabelText` calls picked up stale DOM elements left mounted by earlier tests in the same file, causing index-based lookups to return the wrong element and mocks to appear uncalled.
- **Fix:** Added an explicit `afterEach(() => cleanup())` in `ControlPanel.test.tsx`, scoped to this file (not the shared `vitest.setup.ts`, to avoid conflicting with parallel sibling-plan worktrees also authoring `.test.tsx` files)
- **Files modified:** `src/components/sandbox/ControlPanel.test.tsx`
- **Verification:** All 4 tests pass individually and as a full suite run
- **Committed in:** `f7c7f8a` (Task 2 commit)

**3. [Rule 1 - Bug] Controlled speed input test failed against a static prop fixture**
- **Found during:** Task 2 (writing the speed-change test)
- **Issue:** `ControlPanel` is a fully controlled component (no local state). Testing `user.clear()` + `user.type("20")` against a static, non-updating `vessel.speed` prop caused each keystroke to be appended to the DOM's stale displayed value (reset to the fixture's original `10` after each render) instead of a genuinely cleared field, producing incorrect call arguments (e.g. `("vesselA", 102)` instead of `("vesselA", 20)`)
- **Fix:** Added a small stateful `ControlledHarness` test-only wrapper component that owns vessel state and re-renders `ControlPanel` with the updated value on each change (mirroring the role `SandboxContainer` will play in 04-06), then asserted on the last call via `toHaveBeenLastCalledWith`
- **Files modified:** `src/components/sandbox/ControlPanel.test.tsx`
- **Verification:** Test passes deterministically
- **Committed in:** `f7c7f8a` (Task 2 commit)

**4. [Rule 3 - Blocking] TypeScript 7.0.2 failed to type `@testing-library/user-event`'s default export**
- **Found during:** Task 2 (`npx tsc --noEmit` verification)
- **Issue:** `import userEvent from "@testing-library/user-event"; userEvent.setup()` produced `TS2339: Property 'setup' does not exist on type 'typeof import(".../index")'` -- TypeScript 7.0.2's NodeNext resolution typed the default import as the whole module namespace rather than the `UserEvent` value the package's own `.d.ts` re-exports as default
- **Fix:** Switched to the package's named export: `import { userEvent } from "@testing-library/user-event"`, which types and runs correctly
- **Files modified:** `src/components/sandbox/ControlPanel.test.tsx`
- **Verification:** `npx tsc --noEmit` passes with zero errors; tests still pass at runtime
- **Committed in:** `f7c7f8a` (Task 2 commit)
