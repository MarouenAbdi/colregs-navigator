## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pointer/form-derived Vessel data -> `applyVesselUpdate` -> `classifyEncounter()` | The single validation choke point this entire phase's UI funnels through before untrusted numeric state reaches the pure domain rules engine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `SandboxContainer.applyVesselUpdate` | mitigate | `VesselSchema.safeParse()` runs on both `nextA`/`nextB` before any state update or `classifyEncounter()` call; a malformed update (e.g. `NaN`/`Infinity` from a buggy handler upstream) is rejected as a no-op rather than reaching the domain layer, per 04-RESEARCH.md's V5 Input Validation guidance |
| T-04-13 | Repudiation / Information Disclosure | Reasoning trail / verdict rendering | accept | all rendered text is either static domain-authored strings (see 04-05's T-04-12) or plain numeric/enum values from already-validated `Vessel` state; no server round-trip, no persisted audit log needed at this phase (persistence is explicitly Phase 5's SCEN-01/SCEN-02 scope, not this phase's) |
| T-04-14 | Denial of Service (client-side) | Continuous drag driving `applyVesselUpdate` on every `pointermove` | accept | `classifyEncounter()` is pure synchronous trig with no I/O; React 19's automatic batching coalesces the `setVesselA`/`setVesselB`/`setLastGoodClassification`/`setIsDegenerate` calls inside one handler into a single render; not adding `useTransition`/throttling is a deliberate CHRT-02 requirement (04-RESEARCH.md Anti-Patterns) |
</threat_model>
