| T-04-11 | Tampering | `ControlPanel`'s `onChange` handlers (`Number(e.target.value)` can produce `NaN` for a cleared/invalid input) | accept | this plan only forwards the parsed value via `onVesselSpeedChange`/`onVesselTypeChange` callback props; it does not persist or trust this data itself -- the actual `VesselSchema` validation boundary is `SandboxContainer.applyVesselUpdate` (04-06's T-04-01), which rejects a `NaN` speed via `VesselSchema.safeParse` before it reaches `classifyEncounter()` |
