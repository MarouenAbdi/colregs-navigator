## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Direct object-literal construction -> cpa() | A caller can construct a `Vessel`-shaped object without going through `VesselSchema.parse()`, so `cpa()` must not assume its inputs are already Zod-validated. |
| Programmer-error literal input -> angle-convert.ts | `angle-convert.ts`'s four functions take plain numbers with no upstream Zod boundary at all (they are not constructed via a schema); a non-finite literal reaching them is treated as a programmer error, not untrusted external input. |
| Static chart configuration -> screen-convert.ts | `containerSize`/`viewBox` originate from a caller's static chart configuration and (in Phase 4) a `ResizeObserver` measurement — not runtime vessel/classification data. This phase treats non-finite or zero-area configuration as a programmer error, mirroring angle-convert.ts's disposition, not a Zod-validated external-input boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Tampering | `src/domain/geometry/cpa.ts` | mitigate | Explicit `Number.isFinite()` guard on all 8 numeric fields across both vessels before any vector arithmetic; returns `err('invalid-input', ...)` instead of propagating NaN/Infinity through `atan2`-adjacent sin/cos/division math. |
