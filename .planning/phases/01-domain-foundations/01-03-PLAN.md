<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Direct object-literal construction -> cpa() | A caller can construct a `Vessel`-shaped object without going through `VesselSchema.parse()`, so `cpa()` must not assume its inputs are already Zod-validated. |
| Programmer-error literal input -> angle-convert.ts | `angle-convert.ts`'s four functions take plain numbers with no upstream Zod boundary at all (they are not constructed via a schema); a non-finite literal reaching them is treated as a programmer error, not untrusted external input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Tampering | `src/domain/geometry/cpa.ts` | mitigate | Explicit `Number.isFinite()` guard on all 8 numeric fields across both vessels before any vector arithmetic; returns `err('invalid-input', ...)` instead of propagating NaN/Infinity through `atan2`-adjacent sin/cos/division math. |
| T-01-04b | Denial of Service | `src/domain/geometry/cpa.ts` (division by `vDotV`) | mitigate | `NEAR_ZERO_RELATIVE_VELOCITY_SQ = 1e-9` epsilon guard prevents division by a near-zero `vDotV` from producing an unstable/huge floating-point result before the division executes — the guard runs before, not after, the division. |
| T-01-05 | Tampering | `src/domain/geometry/angle-convert.ts` | accept | These functions have no external/untrusted input boundary in this phase (they are called with literal/derived numbers from within the domain layer, not directly from user input); a thrown `TypeError` on non-finite input is acceptable here since it signals a programmer error at a call site the domain layer itself controls, not attacker-controlled input. |

</threat_model>
