## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Direct object-literal construction -> bearing()/relativeBearing() | A caller can construct a `Position`/`Vessel`-shaped object without going through `VesselSchema.parse()` (TypeScript structural typing does not enforce runtime validation), so both functions must not assume their inputs are already Zod-validated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02 | Tampering | `src/domain/geometry/bearing.ts` | mitigate | Explicit `Number.isFinite()` guard on all four position coordinates before any `atan2`/normalization arithmetic; returns `err('invalid-input', ...)` (reason established by Plan 01) instead of propagating NaN/Infinity through the calculation. |
| T-01-04 | Tampering | `src/domain/geometry/relative-bearing.ts` | mitigate | Explicit `Number.isFinite()` guard on `own.heading` before subtraction/normalization; `Position`-level non-finite values are already caught by the composed `bearing()` call's own guard (T-01-02), so no duplicate position guard is needed here — only the heading field is unique to this function's own arithmetic. |

</threat_model>
