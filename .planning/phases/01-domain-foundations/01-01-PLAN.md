<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External input -> `VesselSchema.parse()`/`.safeParse()` | Untrusted numeric/string input (eventual chart-sandbox drag values, form inputs, or fixture data) first meets the domain at Vessel/Position construction. This is the domain layer's only validation boundary in this phase. |
| Direct object-literal construction -> geometry functions (Plans 02-03) | TypeScript's structural typing permits constructing a `Vessel`/`Position`-shaped object without ever calling `VesselSchema.parse()` (e.g. `const p: Position = { x: NaN, y: 1 }`), so downstream geometry functions cannot assume Zod already validated their inputs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `src/domain/vessel/vessel.ts` (VesselSchema) | mitigate | Zod's `z.number()` rejects non-finite values (NaN/Infinity) by default; `heading.gte(0).lt(360)` and `speed.gte(0)` reject out-of-range numeric input at construction (D-09/D-10); no `.transform()` is used to silently coerce bad input. |
| T-01-02 | Tampering | `src/domain/shared/result.ts` (`invalid-input` reason reserved here, consumed by Plans 02-03) | mitigate | Establishes the `'invalid-input'` `DegenerateCaseReason` so geometry functions (Plans 02-03) can defensively guard `Number.isFinite()` on all numeric inputs and return a typed `Result` failure instead of propagating NaN/Infinity through `atan2`/`hypot`/division when a caller bypasses `VesselSchema` via direct object construction. |
| T-01-SC | Tampering | npm installs (`zod`, `typescript`, `vitest`) | accept | All three packages are "Approved" in 01-RESEARCH.md's Package Legitimacy Audit. `vitest`'s slopcheck `SUS`/`TYPOSQUAT_RISK` flag is a documented false positive (name-similarity heuristic vs. `vite`; cross-verified HIGH-reputation via Context7, official Vite-ecosystem first-party tool) — no blocking human-verify checkpoint required. |

</threat_model>
