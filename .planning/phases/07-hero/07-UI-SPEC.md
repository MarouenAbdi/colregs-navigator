## Typography

**Body, Label, and Heading roles are unchanged from Phase 6** (SCAF-06 — reused, not redeclared). **Display is corrected from Phase 6's placeholder value**, below.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 13px (Geist Mono for numeric/instrument text; Geist Sans for the eyebrow badge and UI micro-copy) | 600 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 24px | 600 | 1.25 | *(no Hero-owned instance this phase — reserved for Sandbox/Gallery section titles)* |
| Display | **52px** (corrected — see note) | **800** | **1.1** |

**Correction note (Display role):** Phase 6's UI-SPEC registered Display as `48px/600/1.15` as an explicit, self-described **placeholder** ("no Phase-6-owned instance... Display = Hero's headline, Phase 7"). Direct pixel measurement of `Main-Design.png`'s actual headline (3-line block, baseline-to-baseline spacing ≈57px, ascender height ≈39–40px, both converted from the mock's confirmed 2× export scale) resolves to a real font-size of **~52px**, at a visibly heavier weight than 600 — the strokes are extrabold, not semibold. This is consistent with `claude-design-prompt.json`'s typography brief, which explicitly invites "a distinctive display face... for the marketing surface" for the Hero headline, distinct from the app's existing "only two weights used: 400 and 600" baseline (that baseline describes the already-shipped sandbox tool, not the new Hero). **This UI-SPEC's measured value supersedes Phase 6's 48/600 placeholder as Display's real, locked value** — do not use 48/600 for the Hero headline.

Hero's concrete usage of these roles:

- **Headline** ("Two vessels. One rulebook. See who gives way — and why."): Display role, 52px/800/1.1, two-tone color split — "Two vessels. One rulebook." in `--foreground` (white), "See who gives way — and why." in `--accent`/`--primary` (`#2dd4bf`). Responsive: scale down to **36px/800/1.15** below the 640px breakpoint (HERO-04's "scaled headline below 640px" requirement) — same weight/color treatment, smaller size only.
- **Eyebrow badge** ("Collision-avoidance rules engine"): Label role, 13px/600, Geist Mono, `--accent` color, inside a pill-shaped `Badge variant="outline"` with a small solid accent-colored dot before the text.
- **Body copy** (supporting paragraph): Body role, 16px/400/1.5, `--muted-foreground` color, max-width constrained to ~46-50 characters/line to match the mock's 4-line wrap.
- **CTA labels** ("Open the sandbox", "Classic encounters"): Label-adjacent, 16px/600 (shadcn `Button` `size="lg"` default text treatment — not a new size, matches Body's 16px but at Label's 600 weight).
- **Trust note** ("Grounded in Rules 11–18..."): Label role, 13px/400 (with "Rules 11-18" segment bolded to 600 inline), `--muted-foreground`, paired with a small `--accent`-colored checkmark/shield icon (16px).
- **Preview card header row** ("Live classification" / "BRG-ring · 12 NM"): Label role, 13px, Geist Mono, `--muted-foreground` (with the "Live classification" text itself in `--foreground` for contrast against its accent dot).
- **Preview card rule banner** ("Crossing — Vessel A gives way"): Body role, 16px/600 (bumped from Body's default 400 — this is a verdict-style statement, not paragraph copy), `--foreground`, next to a `Rule 15` `Badge` chip (13px/600 Label role, `--primary`/`--primary-foreground`).
- **Preview card readout tiles** (RANGE/BEARING/CPA): two-tier — tile label ("RANGE") is Label role at 13px/600, `--muted-foreground`, Geist Mono, uppercase, letter-spaced; tile value ("2.99 NM") is a **new, Hero-introduced instrument-value size**: **18px/600, Geist Mono, `--foreground`**. This is the first instance of this "big mono instrument-value" pattern in the app — Phase 8 (Sandbox restyle) will reuse this exact 18px/600/mono convention for its own RANGE/BEARING/CPA/TCPA tiles rather than inventing a second one (SBOX-02 will consume this, not redeclare it).
- **Vessel circular labels** ("A"/"B") and **role pills** ("GW"/"SO"): Label role, 13px/600, white text, on solid-color circular/pill backgrounds (see Color section — domain-locked colors, not the accent).

## Color

**Dominant/Secondary/Accent chrome tokens are unchanged from Phase 6** (SCAF-06 — reused, not redeclared):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#09090B` (`--background`) | Hero section background — same as page, no visually distinct section background |
| Secondary (30%) | `#18181B` (`--card`) for the preview `Card` surface; `#27272A` (`--border`) for the Card's outer border, the chart-inset box's border, and the readout tiles' borders | Preview `Card` container; chart-inset box; RANGE/BEARING/CPA tile borders |
| Accent (10%) | `#2dd4bf` (`--primary`/`--accent`) | Reserved for: the headline's final clause ("See who gives way — and why."), the eyebrow badge's border/dot/text, the primary CTA's filled background, the "Live classification" indicator dot, the rule banner's `Rule 15` chip fill, the rule banner's background tint (`bg-primary/10`–`/15`) and border tint (`border-primary/30`–`/40`), the mini-chart's range-ring stroke and sector-fill gradient, and the trust-note checkmark icon. **Not used** for the outline CTA's fill, body copy, or any GW/SO/domain-role element (those use the locked domain-semantic colors below, never the chrome accent). |
| Destructive | shadcn default (`--destructive`) | Not exercised this phase — Hero has no destructive actions |

**Domain-semantic colors (LOCKED, first real usage this phase):** `claude-design-prompt.json`'s `domain_semantic_colors_LOCKED_do_not_change` block defines these; Phase 6 deferred them ("belongs to Phase 8"), but Hero's illustrative preview card (HERO-02) needs them **now**, ahead of Phase 8's Sandbox restyle. Pixel-sampled directly from `Main-Design.png` and confirmed to match the locked hex values exactly:

| Domain color | Hex | Usage in Hero's preview card |
|---|---|---|
| Give-way vessel hull | `#EF4444` (red-500) | Vessel A's triangle fill; the "GW" pill background (white text) |
| Stand-on vessel hull | `#22C55E` (green-500) | Vessel B's triangle fill; the "SO" pill background (white text) |
| Bearing line (normal) | `#475569` (slate-600) | The solid range/connecting line between Vessel A and Vessel B |
| Doubt/ambiguous | `#F59E0B` (amber-500, dashed) | Not used in this fixture (fixture has `doubt: false`) — declared here for completeness only, no Hero instance |

**Contract (per research Pattern 3, locked):** These domain colors must be **hardcoded directly inside `Hero.tsx`** as Tailwind arbitrary-value classes (e.g. `fill-[#EF4444]`, `bg-[#22C55E]`) or inline SVG `fill`/`stroke` attributes — **do not** import `src/components/sandbox/vessel-role.ts` (feature-boundary violation, and its `HULL_FILL_CLASS` is still unreamed light-mode Tailwind classes Phase 8 hasn't fixed yet) and **do not** create a new `shared/vessel-role-colors.ts` "to be safe" (explicitly the exact anti-pattern `PITFALLS.md` Pitfall 1 warns against). The "GW"/"SO" **label text** must be derived from `classification.giveWay`/`classification.standOn` (not hand-typed), so a future fixture change can't silently desync the badge text from the computed verdict; the **colors** may stay hardcoded since the fixture's verdict (`giveWay: "vesselA"`) is fixed at authoring time.

Accent reserved for: headline emphasis clause, eyebrow badge, primary CTA fill, live-indicator dot, Rule-15 chip fill, rule-banner tint, chart range-ring/sector, trust-note icon. Never used for GW/SO badges, hull colors, or the bearing/connecting line (those are domain-locked, not chrome).

## Executor Notes (supplementary — not template-required, carried from research + this session's direct image measurement)

### Preview Card Dimensions (corrects 07-RESEARCH.md's placeholder)

07-RESEARCH.md flagged `HERO_CONTAINER_SIZE = { width: 280, height: 280 }` as an explicit "starting point... tune visually" guess (Open Question 1). Direct pixel measurement of `Main-Design.png`'s preview card resolves this:

- The mini-chart inset box is **not square** — it measures roughly **8:5 (≈1.6:1) wide-to-tall**, not 1:1. Set `HERO_VIEW_BOX`'s width/height ratio to match (e.g. `{ width: 8, height: 5 }`-proportioned chart-space units, framed to comfortably contain both fixture vessels and the range ring), not a square viewBox.
- The Card itself should be **fluid-width** (fills the right column of the two-column grid, not a fixed pixel width) — let the SVG's native `viewBox` scaling (Research Pattern 1) handle responsiveness across breakpoints, exactly as already planned. Do not hardcode a fixed card width in px.

### Two-column layout

- Desktop (≥900px): two-column layout, roughly equal-width columns (headline/copy/CTAs column | preview-card column), `gap-12`/48px (2xl spacing token) between them, vertically centered.
- Below 900px (CONTEXT.md D-04): single column, headline/copy/CTAs stack above the preview card, text-first order preserved in DOM (do not use CSS order to reverse — keep source order matching visual order for accessibility).

### Rule banner exact color derivation (for implementation reference)

Pixel-sampled from `Main-Design.png`: rule-banner background ≈ `--primary` at ~12-15% opacity over `--card`/`--background` (`bg-primary/10` to `bg-primary/15` is a close Tailwind-idiomatic match), border ≈ `--primary` at ~30-40% opacity (`border-primary/30` to `/40`). The `Rule 15` chip itself is **solid, full-opacity** `--primary` background with `--primary-foreground` text — sampled hex `#2ad4bf`, an exact match to the registered `--primary`/`--accent` token (`#2dd4bf`), confirming no new color value is needed for the chip.

### Anchor/scroll wiring (HERO-03)

- Land `id="sandbox"` on a **new wrapper element in `app/page.tsx`** around the existing `<SandboxContainer />` (e.g. `<section id="sandbox"><SandboxContainer /></section>`) — do **not** edit `SandboxContainer.tsx` itself (Pitfall H1: its current root is already a stray nested `<main>`, out of this phase's scope; Phase 8 owns that cleanup).
- Both CTAs use plain `<a href="#sandbox">` / `<a href="#gallery">` wrapped in `Button asChild`, exactly matching `Header.tsx`'s already-shipped "Source" link composition. No `next/link`, no `scrollIntoView()` `useEffect`, no JS scroll library (D-05; Pitfall H2 confirms Pitfall 6's route-to-anchor concerns don't apply to same-page `<a>` clicks).
- `#gallery` remains a no-op until Phase 9 ships (D-06, carried forward, not re-decided) — do not build a temporary fallback.

### Fixture data (HERO-02, D-07 — verified, not re-derivable by planning)

Use the exact fixture from `07-RESEARCH.md`'s Code Examples section (`heroPreviewVesselA`/`heroPreviewVesselB`) — computed via the real `classifyEncounter()`/`bearing()`/`cpa()` formulas, reproduces RANGE 2.99 NM / BEARING 061° / CPA 1.18 NM / Rule 15 Crossing / Vessel A gives way essentially exactly. Do not hand-type these numbers as literal strings disconnected from a real `classifyEncounter()` call.

### Dark-mode-only, no new tokens beyond Phase 6 + this document

No `next-themes`, no toggle, no `.dark`-class machinery — Hero renders under the same single dark palette Phase 6 already locked (`className="dark"` on `<html>`, unchanged).
