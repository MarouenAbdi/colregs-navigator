ESLint's own flat-config migration guide (Context7 `/eslint/eslint`, fetched this session) documents the exact "local plugin" pattern for a repo-local custom rule, replacing the deprecated `--rulesdir` flag: register `plugins: { local: { rules: { "rule-name": ruleModule } } }`, then `rules: { "local/rule-name": "error" }`.

`no-restricted-syntax`'s `selector` option matches ESTree AST node types via esquery (e.g. `JSXAttribute`, `TemplateLiteral`, `TemplateElement`) -- it does NOT match comments (comments are not part of the traversed AST). Comment-text matching requires a rule that calls `context.sourceCode.getAllComments()` directly -- hence the stale-ID check is a small local custom rule, not a `no-restricted-syntax` selector.
