<objective>
Wire the thin tRPC adapter layer on top of Plan 02's application service: initialize tRPC, compose the `scenario` and `gallery` routers, and expose them over Next.js's App Router via a catch-all route handler. Prove SCEN-02's re-derive-on-read guarantee end-to-end (router -> service -> repository -> domain) with `createCallerFactory`-based integration tests, without requiring a running HTTP server.

Purpose: This is the phase's final layer -- routers must stay pure Zod-validated pass-throughs (D-10/D-11, success criterion #4) with zero classification logic or direct Prisma calls, so `classifyEncounter()` and Prisma both remain reachable only through Plan 02's service.
Output: `scenario`/`gallery` tRPC routers, the composed `appRouter`, the Next.js route handler, and an integration test proving a full create -> get round trip re-derives the verdict correctly.

**Scope boundary (Open Question 2, resolved in Plan 01):** this plan verifies the routers via `createCallerFactory` (server-side, no HTTP round trip needed) -- it does NOT create a `TRPCReactProvider`, `layout.tsx` wiring, or any client-side hook consumer. That scaffold is explicitly deferred to Phase 4, which is the first phase with a UI to consume it.
</objective>
