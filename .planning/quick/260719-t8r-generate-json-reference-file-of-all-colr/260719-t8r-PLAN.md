<audit_findings>
This dispatch-tree analysis was already performed by the planner (full read
of `classify-encounter.ts`, `types.ts`, `vessel-priority.ts`,
`risk-of-collision.ts`, `vessel.ts`, and cross-checked against every case in
`classify-encounter.fixtures.ts`), so the executor does not need to
re-derive the tree shape from scratch -- re-read the source only to copy
literal strings verbatim and sanity-check this breakdown before writing.

`classifyEncounter()` pushes an ordered `ReasoningTrailEntry[]` (`{ruleId,
text, facts}`) at each dispatch stage. Every `text` value in the function is
a fixed literal string (never runtime-templated) -- 14 distinct literal
strings total, combining into exactly **7 distinct full end-to-end trail
shapes**, plus 2 Stage-0 `Result` failure reasons that short-circuit before
any trail is built. This is the complete, exhaustive set -- no other paths
exist through the function:

**1. `overtaking-sticky-hysteresis`** -- `effectivePrevious === "overtaking"`
   branch. Trail = [Rule 7, Rule 13(d) sticky, Rule 13(a) "Rule 18 does not
   apply to an overtaking situation..."]. `riskOfCollision` always `true`
   (hysteresis only reachable when Rule 7's gate holds). `giveWay`/`standOn`
   direction depends on `|rbAtoB| >= |rbBtoA|` tie-break (not a distinct
   trail-text shape, note both directions as possible outcomes of this one
   shape). Example fixtures: `overtakingHysteresisHoldsCase`,
   `overtakingHysteresisNearBoundaryCase`.

**2. `overtaking-fresh-b-gives-way`** -- fresh dispatch, `bOvertakesA` true.
   Trail = [Rule 7, Rule 13(a)-(b) "Vessel B is overtaking Vessel A...",
   Rule 13(a) no-Rule-18 text]. `giveWay="vesselB"`, `standOn="vesselA"`.
   `riskOfCollision` can be true or false. Example fixtures:
   `overtakingBothDirectionsCase`, `overtakingRule18NoOverrideCase`,
   `doubtBandJustOverOvertakingBoundaryCase`.

**3. `overtaking-fresh-a-gives-way`** -- fresh dispatch, `aOvertakesB` true
   (and `bOvertakesA` false, or the WR-02 both-true tie-break). Trail =
   [Rule 7, Rule 13(a)-(b) "Vessel A is overtaking Vessel B...", Rule 13(a)
   no-Rule-18 text]. `giveWay="vesselA"`, `standOn="vesselB"`. Example
   fixture: `overtakingBothTrueDivergingCase` (riskOfCollision false).

**4. `head-on-rule18-override`** -- not overtaking, head-on true, Rule 18
   priorities differ. Trail = [Rule 7, Rule 13(a)-(b) "Not overtaking...",
   Rule 14(a)-(b) head-on text, Rule 18(a)-(c) "Rule 18 hierarchy applies
   even to a head-on encounter..."]. `giveWay`/`standOn` populated per
   priority. `doubt` always `true`, `doubtBoundary`
   `"near-head-on-boundary"` (Assumption A1: the head-on sector IS the
   doubt band). Example fixture: `headOnRule18OverrideCase`.

**5. `head-on-mutual-obligation`** -- not overtaking, head-on true, Rule 18
   priorities equal (including the NUC/RIATM tie). Trail = [Rule 7, Rule
   13(a)-(b) "Not overtaking...", Rule 14(a)-(b) head-on text, Rule 18(a)-(c)
   "Rule 18 does not apply: both vessels share the same priority tier..."].
   `giveWay=null`, `standOn=null`. `doubt` always `true`. Example fixtures:
   `headOnGenuineCase`, `headOnBoundaryInclusiveCase`,
   `headOnNucRiatmTieCase`, `headOnInDoubtCase`.

**6. `crossing-rule18-override`** -- not overtaking, not head-on (residual
   Rule 15 crossing), Rule 18 flips the geometric baseline. Trail = [Rule 7,
   Rule 13(a)-(b) "Not overtaking...", Rule 14(a)-(b) "Not head-on...", Rule
   15 crossing text, Rule 18(a)-(c) "Rule 18 override: ...verdict
   flipped."]. `giveWay`/`standOn` are the geometric baseline's labels
   swapped. Example fixture: `crossingRule18OverrideCase`.

**7. `crossing-no-rule18-override`** -- same dispatch path as #6, but Rule
   18 does not override. Trail = [Rule 7, Rule 13(a)-(b) "Not
   overtaking...", Rule 14(a)-(b) "Not head-on...", Rule 15 crossing text,
   Rule 18(a)-(c) "Rule 18 does not override the geometric baseline..."].
   `giveWay`/`standOn` are the geometric baseline (`rbAtoB > 0` ?
   `vesselA`:`vesselB` gives way). Example fixtures:
   `crossingResidualBasicCase`, `headOnPitfall2OneSidedCase`,
   `crossingRule18NonOverrideCase`, `crossingSailingPriorityCase`,
   `crossingNotUnderCommandCase`, `doubtBandNearOvertakingBoundaryCase`,
   `justOutsideHeadOnSectorCase`, `deadAheadNonReciprocalCase`,
   `noClosureDoesNotPropagateCase`.

**Stage-0 `Result` failures (no trail is ever built for these -- the
function returns `!ok` before pushing anything to `trail`):**
- `coincident-position` -- propagated unchanged from `relativeBearing()`
  when the two vessels occupy the same position. Example fixture:
  `stage0CoincidentPropagationCase`.
- `invalid-input` -- propagated unchanged from `relativeBearing()`/`cpa()`
  for any other invalid-geometry input.

Rule 7's entry (`ruleId: "Rule 7"`) always appears first in every one of the
7 shapes above -- its `text` has exactly 2 literal variants (risk / no
risk), and `facts.tcpaMinutes`/`facts.dcpaNm` are only present when
`cpaResult.ok` is true (omitted on a degenerate no-closure `cpa()` result).

Do not invent an 8th shape, a 15th literal string, or any fact key beyond
the 7 already rendered by `ReasoningTrail.tsx`'s `FACT_LABEL` record
(`riskOfCollision`, `tcpaMinutes`, `dcpaNm`, `relativeBearingAtoB`,
`relativeBearingBtoA`, `vesselAType`, `vesselBType`).
</audit_findings>
