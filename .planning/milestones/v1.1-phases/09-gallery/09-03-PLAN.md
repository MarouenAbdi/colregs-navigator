<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser (fresh tab / bookmark to `/gallery`) -> Next.js server routing layer | The redirect's `destination` is a hardcoded string literal in `next.config.ts`, never derived from request-supplied input (query params, headers, referrer) -- no open-redirect surface exists |
| Browser -> `GalleryContainer` (async Server Component) | Server-side data fetch via the existing public, read-only `gallery.list()` tRPC query -- unchanged contract, no new input surface |
| User click -> `<Link href="/s/{id}">` | Client-side navigation only, no state mutation, no data submitted -- `id` values come from the server-rendered `scenarios` array itself, never reflected from user input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-06 | Tampering (open redirect) | `next.config.ts` `redirects()` | accept | `source`/`destination` are both static string literals with no template/query-param interpolation -- there is no code path by which a request could redirect anywhere other than the one hardcoded `/#gallery` destination |
| T-09-07 | Information Disclosure | `GalleryContainer`'s `gallery.list()` call | accept | Unchanged, already-public read-only query (curated demo scenarios only, no user/session data) -- identical trust level to the route it replaces |
| T-09-08 | Denial of Service | `GalleryContainer` server-side render | accept | Bounded, deterministic work per request (6 curated rows, each re-deriving one `classifyEncounter()` call) -- same cost profile as the existing `app/gallery/page.tsx` it replaces, no new unbounded loop |

No npm/pip/cargo package installs occur in this plan -- the Package Legitimacy Gate is not triggered.
</threat_model>
